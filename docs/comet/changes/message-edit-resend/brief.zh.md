# 目标

[English](brief.md) | 中文

用户可以在当前聊天编辑最新一条已发送的用户消息，并用修改后的内容重新请求模型回答。用户调整历史消息时，先从对应已完成轮次开分支到新聊天，再编辑新聊天中的最新用户消息。

# 范围

在聊天界面仅为最新一条已发送的用户消息提供编辑入口、文本编辑、取消和重新发送操作；历史消息沿用开分支到新聊天的流程。运行中禁用编辑，结束或用户手动停止后可编辑；只修改文字，原附件保持不变。同步实现必要的会话 API、历史记录投影、持久化重放和中文、英文界面文案。

# 非目标

不在原聊天直接编辑历史用户消息，不编辑助手回答或工具结果，不增加同一聊天的消息版本切换界面，不自动停止运行，不增加或删除原消息附件，不自动撤销原对话已经产生的文件修改、命令执行或外部操作。是否重新执行工具取决于模型收到修改后消息的回答过程。

# 验收示例

编辑后取消时，原消息、原回答和原会话历史保持完整；取消不请求模型，也不执行工具。

最新用户消息在当前聊天修改重发时，模型历史采用该消息之前的对话和修改后的输入；原用户消息及其后续回答不能作为修改后输入之前的历史继续传给模型。当前聊天展示修改后的消息和新回答，已提交的原始日志保持可重放。

从历史消息所在已完成轮次开分支后，该用户消息成为新聊天中的最新用户消息并可编辑；重发只影响新聊天，原聊天的消息和后续回答保持完整。

输入无效或提交失败时，界面显示可理解的原因并保留编辑草稿；重试不得重复提交同一消息。附件保持可查看且不重复上传。完整验收场景在本变更的 specs/message-edit-resend/spec.md 中定义。

# 约束与不变量

会话日志保持可重放，已经提交的事件不得原地覆盖或删除；所有模型可见输入必须有对应日志记录。原对话的外部副作用不会因为编辑重发而回滚。

现有聊天分支按钮位于已完成轮次的最后一条消息；现有远端 fork API 将锚点解析到该轮的 turn/end。历史调整沿用该分支结果，使目标用户消息成为新聊天中的最新用户消息。编辑重发本身仍需要排除被编辑的原输入及其后续历史。

最新用户消息的编辑资格不因它来自分支继承历史而失效。服务端提交时重新核对目标仍为最新用户消息，防止其他客户端的新输入使草稿目标过期。

实现必须覆盖首条消息、后续消息及日志重放。产品界面文案由类型化语言字典管理；测试和录制遵循仓库现有会话快照、GUI 及真实模型验证要求。

# 决策

沿用已创建的独立 worktree 和 Comet Native 变更 message-edit-resend；需求确认前不修改产品实现。

本功能的聊天入口、会话历史和重发操作共同构成一个验收目标，保持单个变更。

Q1 已确认：只允许编辑最新一条用户消息。

Q2 的历史调整路径已确认：用户想调整历史消息时，开分支到新聊天；最新消息按当前聊天编辑重发的方向编写规格，不引入消息版本切换界面。

Q3 已确认：运行中禁用编辑；结束或用户手动停止并完成清理后可编辑。

Q4 已确认：只修改文字，保留原附件。
