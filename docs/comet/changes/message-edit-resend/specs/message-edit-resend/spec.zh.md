# 最新用户消息编辑重发

[English](spec.md) | 中文

用户可以编辑当前聊天中最新一条已发送用户消息的文字并重新请求模型回答。历史消息通过分支到新聊天调整；运行中禁用编辑，原附件保持不变。

## 编辑资格

当前聊天仅最新一条已发送的用户消息具有编辑资格。助手回答、工具结果和更早的用户消息没有直接编辑入口。新聊天中从分支继承的最新用户消息同样具有编辑资格；分支父聊天保持完整。排队输入继续采用已有队列编辑操作，不视为已发送聊天消息。

### Scenario: 仅最新用户消息可编辑

聊天包含用户消息 A、助手回答 A、用户消息 B、助手回答 B。用户可编辑 B；A 没有直接编辑入口。助手回答 B 不影响 B 作为最新用户消息的资格。

### Scenario: 首条用户消息可编辑

聊天只有一条已发送用户消息 A 和它的回答。用户可编辑 A；重发请求不得包含原 A 和原回答，也不得因没有更早用户消息而拒绝编辑。

## 编辑与重发

编辑入口打开预填原文字的编辑器，用户可以取消或提交修改后的输入。重发在当前聊天展示修改后的消息及新回答；模型收到的是该用户消息之前的有效历史和修改后的输入。已提交日志不原地删除或覆盖，重新加载和持久化恢复得到同样的有效对话。

### Scenario: 取消编辑

用户修改最新消息后取消。聊天恢复原消息和原回答；没有新增模型请求或工具执行。

### Scenario: 最新消息重发排除原输入和原回答

聊天包含 A 及其回答、B 及其回答。用户把 B 改为 B2 并提交。当前聊天展示 A 及其回答、B2 及新回答。模型历史包含 A 及其回答和 B2，不包含原 B 或原 B 回答。

### Scenario: 重发后的持久化恢复

最新消息修改重发并保存后，用户重新加载聊天或重启服务。展示和模型有效历史仍采用修改后的输入及新回答，日志保留可重放的原始事件和修改操作记录。

### Scenario: 草稿目标过期

客户端一开始编辑消息 B，提交前聊天已接受更新的用户消息 C。服务端拒绝针对 B 的编辑提交，客户端保留草稿并告知目标已不是最新用户消息；模型不收到该编辑请求，C 不受影响。

### Scenario: 同一消息被其他客户端修改

两个客户端同时编辑最新消息 B，一个客户端先成功提交 B2。另一个客户端基于原 B 提交时被拒绝，草稿保持可恢复，不覆盖 B2，也不产生额外模型请求。

## 运行状态

模型回答、工具执行以及停止清理期间均禁用编辑。用户手动停止后，只有服务端确认该运行已经结束才能重新编辑。编辑器打开期间若聊天重新开始运行，界面禁用提交；服务端独立检查运行状态并拒绝过期提交，保留草稿，不自动停止运行。

### Scenario: 运行中禁用编辑

最新消息正在等待模型回答或执行工具。编辑入口不可操作并给出本地化原因；用户不能通过此入口中断原运行。

### Scenario: 手动停止后编辑

用户手动停止运行，停止和工具清理尚未完成时仍不能编辑。服务端确认运行结束后，该聊天的最新用户消息恢复编辑资格。

### Scenario: 编辑期间开始新运行

编辑器已经打开，聊天随后开始运行。客户端禁用提交并保留草稿；直接向服务端发送编辑请求也被拒绝，现有运行不会被自动停止。

## 附件与内容校验

编辑器展示原消息附件，只允许修改文字；用户不能通过编辑操作增加、删除或替换附件。重发继续引用原附件，不重复上传。文件引用和其他非文字内容按原有顺序保留，不将展示文本重新解析为新的附件或文件上传。

### Scenario: 修改文字保留附件

最新用户消息包含文字和多个附件。用户修改文字后提交，修改后的消息和模型请求保留原附件的身份、顺序和内容；界面不提供附件增删操作，不重复上传。

### Scenario: 只有附件的有效输入

用户将文字清空，但消息仍有有效原附件。重发保留附件并按现有附件输入规则接受该输入；不存在文字和附件的空白输入则被拒绝，草稿和原对话保留。

### Scenario: 原附件无法读取

重发需要的原附件不可用。系统告知失败原因，不静默丢弃附件，不用部分输入请求模型；用户文字草稿保持可恢复。

### Scenario: 提交内容没有变化

用户进入编辑器后未改变文字，或将文字恢复为原内容。界面不发起重发请求，不重复调用模型或工具。

## 失败与重试

提交被接受前，校验或网络失败不替换原有效对话，编辑器保留草稿和可理解的失败提示。相同操作的重试使用稳定请求标识；服务端已经接受的操作即使目标因该操作改变，也返回原接受结果而不再次生成输入。提交已被接受后模型失败，聊天保留修改后的消息并使用已有失败展示和恢复操作，不悄悄恢复原输入。

### Scenario: 提交前失败

用户提交有效文字，但操作未被接受即失败。原消息和原回答保持完整；界面保留草稿并允许重试，失败操作没有请求模型。

### Scenario: 接受结果丢失后重试

服务端已经接受编辑重发，但客户端未收到响应。客户端以相同请求标识重试，返回同一接受结果；只记录一次修改输入，只启动一次新回答。

### Scenario: 接受后模型失败

编辑请求已经被接受，模型随后失败。聊天仍展示修改后的输入及失败状态，用户可以使用已有恢复操作；系统不将原消息和原回答恢复为当前有效历史。

## 历史消息调整

用户通过现有已完成轮次的分支操作进入新聊天；分支保留该轮及之前的历史，使该轮最后一条用户消息成为新聊天中的最新用户消息。用户在新聊天编辑重发，父聊天和它的后续对话保持完整。

### Scenario: 分支继承的最新消息可编辑

父聊天有 A 及其回答、B 及其回答。用户从 A 对应回答末尾开分支，进入包含 A 及其回答的新聊天；A 具有编辑资格。用户将 A 改为 A2 并重发，新聊天采用 A2 和新回答，父聊天的 A、B 和原回答均保持完整。

## 外部操作

修改对话历史不会撤销已经完成的文件修改、命令执行或外部操作。模型对修改后的输入作答时可能再次调用工具。

### Scenario: 外部副作用不回滚

原回答过程已经修改文件。用户编辑最新消息重发，或在分支中调整消息。编辑和分支操作本身不撤销该文件修改。

## 展示与可访问性

编辑入口、输入框、取消、重新发送、禁用原因及错误提示均支持当前中文和英文界面，并具有本地化可访问名称。编辑操作支持键盘使用，取消或提交后焦点回到合理的聊天位置。

### Scenario: 中英文与键盘操作

用户在中文或英文界面通过键盘打开编辑、修改文字、取消或重新发送。编辑控件具有对应语言的名称，禁用和错误原因可感知，焦点不会因编辑器关闭而丢失。
