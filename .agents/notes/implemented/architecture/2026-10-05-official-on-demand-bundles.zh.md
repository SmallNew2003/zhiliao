# Agent Note: 在 profile 安装前发现 Official bundle

Status: implemented

[English](2026-10-05-official-on-demand-bundles.md) | 中文

## 问题

原生子智能体集成携带自己的运行时。把这些依赖放进每次 DSH 安装，会让从不向它们委派任务的用户也承担成本；要求用户知道包名，又会让插件页无法展示这些集成。

## 决策

`ON_DEMAND_BUNDLES` 将 Claude Code、Codex 和 CUA bundle 纳入安装方维护的目录。目录内嵌包自身拥有的本地化元信息和图标，因此发现过程离线可用，无需解析或导入这些包。Official 表示项目维护；可选交付与实验成熟度仍是独立属性。

选择操作复用普通第三方 bundle 的安装器、profile 依赖、Host 行 patch、兼容性判断、进度、取消和构建脚本审批。原生认证与配置仍由提供方拥有。

[安装介质携带的交付决策](2026-11-07-installation-carried-official-bundles.zh.md)取代注册表交付及不在安装依赖中携带这些运行时的政策。它负责本地目标解析、同版本验证和不完整安装错误。当前运行的安装决定目标，不由当前工作目录或预发布版本后缀决定。替换已安装的注册表副本或其他 checkout 的链接时，同时比较来源和版本。替换需显式触发，保留选择状态，并报告是否需要重启；启动时不下载提供方。[插件管理器](../../../../packages/boot/plugin-manager/README.zh.md#use-this-package)拥有操作细节。

所有 Official 包仍属于 DSH 发布家族。打包后的 DSH 依赖、可选依赖与 peer 均使用家族精确版本。目录校验拒绝缺失的元信息、不受支持的成员和过期生成内容。

[随附可选 bundle 策略](../process/2026-09-15-shipped-optional-bundles.zh.md)仍管理安装随附的轻量 bundle。[可选组合决策](2026-09-21-experimental-capabilities-as-optional-bundles.zh.md)管理共享 patch 行为与全局可选工具。原生 bundle 插入普通 Host 行，因此任何 profile 都可以选择它们；保留包但不选择其 bundle 的 profile 显式挂载相同的行。[身份兼容决策](2026-10-06-web-desktop-plugin-identity-compatibility.zh.md)管理保留名称、选择器和暂缓的命名清理。

## 考虑过的替代方案

**每次安装都附带原生运行时。** 会为未使用的集成增加默认下载量。[安装介质携带的交付决策](2026-11-07-installation-carried-official-bundles.zh.md)接受这一成本，使尚未发布到注册表的产品版本也能分发。

**查询注册表构建发现列表。** 可以避免内嵌元信息，但发现过程依赖网络可用性，且无法把提供的包版本绑定到运行中的应用。

**为 Official 包增加独立安装器或激活注册表。** 第二条路径会重复包操作和 profile 组合行为。安装方维护的发现数据可以复用已有第三方机制。

**始终安装与当前版本相同的注册表包。** 版本相同可以标识已发布版本，但不能标识尚未发布的源码修改。这可能向期待当前工具贡献的开发 Host 交付旧提供方 API 和仅含提供方的 patch。

**建立独立的开发注册表或产物缓存。** 普通本地链接已能让提供方代码及其依赖来自当前 checkout。第二套交付系统会增加生命周期和失效处理，而不改善这一开发保证。

## 后果

本地交付要求完整安装或准备并构建 checkout，并遵循正常的重新构建和重启流程。源码版本字符串相同不证明构建输出相同。关闭仅取消选择；移除保持独立，并在 bundle 的行仍在使用时拒绝执行。移除 profile 依赖不删除安装携带的副本。激活失败可以保留已保存的依赖和选择，不加入回滚。离线元信息与 profile 生命周期仍由本记录负责；安装介质携带的交付及其验证由链接的决策负责。原生提供方认证不属于目录发现过程。
